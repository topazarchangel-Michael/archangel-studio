Adding AI to your own app

How to give an app you built a "brain" of its own — safely.

The golden rule: never put a key in your app

Anything in a web app's code can be read by anyone who opens it. If you put an API key there, strangers can use it and you may get the bill.

Three safe ways

WayGood forKey safety
No AI — rules and templatesQuizzes, trackers, simple gamesNothing to leak
User brings their key — they paste it into a Settings box, saved only in their browserTools for yourself and friendsEach person's key stays on their device (this is how Archangel works)
A small proxy — a free Cloudflare Worker holds the key and passes messages onApps for lots of peopleKey lives only in the Worker's secret settings

Step by step: user-brings-their-key

  1. Ask ULTRA in the Builder: "Add a Settings screen where the user pastes their own Gemini key, saved in localStorage, never in the code."
  2. Most providers (Gemini, Groq, OpenRouter, xAI) accept the OpenAI-style chat format, so the same code works with a different web address and model name.
  3. Add a Test button and friendly error messages (wrong key, limit reached, offline).

Step by step: a proxy (more advanced)

  1. Make a free Cloudflare account.
  2. Use the workers/ultra-proxy example in the Archangel source as a starting point.
  3. Store the key with wrangler secret put — never in a file.
  4. Add limits (per-person, per-day) so nobody can run up your usage.

Running AI on the device

  • WebLLM runs small open models (like Qwen) in the browser with WebGPU — this is what Archangel's on-device brain uses. Free and private, but needs a decent device.

Be honest with users

  • Tell them which AI is used and where their words go.
  • Say that AI can be wrong.
